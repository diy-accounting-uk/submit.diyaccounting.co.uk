# RA1: the Rates and allowances page and its calculator

This is the build brief for NEXT.md row RA1. It names every file, function, input and test. Build
it on top of MTD1's commit (branch `claude/sequoia-mtd1`), which brings the `tax-sources` skill,
`scripts/verify-tax-sources.mjs`, `scripts/build-mtd-calendar.mjs`, `web/unit-tests/mtdCalendar.test.js`
and the "MTD calendar" nav entry. If a name MTD1 landed differs from the names quoted here, use
MTD1's name.

## 1. What the page is

`web/public/rates.html`, generated by `scripts/build-rates-page.mjs` in the same way
`build-mtd-calendar.mjs` generates `mtd-calendar.html` (a template string, formatted with
prettier, committed). It has three parts, in this order:

1. The calculator.
2. Rate tables, one per topic, a column per year, each cell a fact with a source.
3. Sources: one entry per source file, with its quote, link and retrieval date.

Years shown:

| Constant | Value | Engine files |
|---|---|---|
| `TAX_YEARS` | `["2025-26", "2026-27"]` | `se-2025-2026.toml`, `se-2026-2027.toml` |
| `FINANCIAL_YEARS` | `[2025, 2026]` | `ltd-2025.toml`, `ltd-2026.toml` |

Add 2027 to `FINANCIAL_YEARS` only if a gov.uk page states the FY2027 corporation tax main rate.
`ltd-2027.toml` says its own figures are provisional and carried forward from FY2026. The
calculator offers only these years, so every figure it uses has a source on the page.

## 2. How the engine reaches the page

### Decision

Copy five engine modules verbatim from the npm package Submit already depends on, serve them
from Submit's own origin under `web/public/lib/diya-gl/tax/`, and commit the copies. There is no
bundler and no CSP change.

Facts behind it:

- `@diy-accounting-uk/diya-gl` is pinned at `1.2.17` in Submit's `package.json`. Its `dist/`
  ships `dist/app/lib/tax/*.js` and `dist/app/data/{se,ltd}-*.toml`. The package has no
  `exports` field, so Node can import any file under `dist/` by deep path.
- The installed 1.2.17 copies of `app/lib/tax/*.js` and every `se-*.toml`/`ltd-*.toml` are
  byte-identical to the spreadsheets repository's `main` today. The registry's latest is 1.2.38.
- `income-tax.js`, `national-insurance.js`, `corporation-tax.js`, `capital-allowances.js` and
  `mileage.js` have no `import` lines at all. A browser can load them as they are.
- `vat.js` imports `../generator.js` (JSZip, the spreadsheet runner) and
  `../calculators/shared.js`. It stays out.
- Submit's CSP (`EdgeStack.java`, the `-WHP` and `-DiyaGlWHP` policies) is
  `script-src 'self' 'unsafe-inline'` plus the RUM and GTM hosts, with no `unsafe-eval`. A module
  served from `'self'` needs no change. The five modules contain no `eval` or `new Function`.

Rejected options:

| Option | Why not |
|---|---|
| Vendor spreadsheets' `diya-gl-engine.js` bundle (`build-diya-gl-bundle.mjs`) | It is the whole engine (pipeline, ajv validators, resource loader) for five small functions. It is not in the npm package, so Submit would copy it out of the sibling checkout, which CI does not have. |
| esbuild or rolldown bundle built in Submit | Submit has no `esbuild` package, only `rolldown` through vite. The five modules need no bundling. |
| Copy at deploy time, not committed | Three deploy paths (CDK `PublishStack`, `scripts/deploy-app.js`, the local Express server) and the browser tests would each need the copy step. One missed step serves a 404 module. |
| Change the CSP to load the module from `spreadsheets.diyaccounting.co.uk` or `diya-gl.co.uk` | Widens `script-src` to a second origin for every Submit page, and ties Submit's page to another site's deploy. |
| Read the sibling checkout `../spreadsheets.diyaccounting.co.uk` | CI has no sibling checkout. |

### Pinning and refresh

- The version pin is `package.json`'s `"@diy-accounting-uk/diya-gl": "1.2.17"`.
- `scripts/build-rates-page.mjs` copies the five files from
  `node_modules/@diy-accounting-uk/diya-gl/dist/app/lib/tax/` to `web/public/lib/diya-gl/tax/`, and
  writes the version it copied from into `rates-data.js` as `ENGINE_VERSION`.
- `web/unit-tests/ratesPage.test.js` fails when a committed copy differs from the installed
  package's file, or when `ENGINE_VERSION` differs from the installed package's version.
- Refresh: bump the pin (`npm install --save-exact @diy-accounting-uk/diya-gl@<version>`), run
  `npm run build:rates-page`, run the tests, commit. The same dependency serves the company-book
  work, so a bump is a deliberate change of its own.
- Engine figures that disagree with gov.uk are fixed in the spreadsheets repository's
  `app/data`, published as a new diya-gl version, then pulled in by the bump above. Submit never
  patches the copies.

### Licence

The copies keep their own `// SPDX-License-Identifier: Apache-2.0` header. Add
`"web/public/lib/diya-gl/"` to `EXCLUDED_PATH_PREFIXES` in `app/unit-tests/licenceHeaders.test.js`,
to the ignore list in `eslint.config.js` (beside `web/public/lib/qrcode.min.js`) and to

## 6. Facts and sources

### Fact definitions in `scripts/build-rates-page.mjs`

```js
export const TAX_YEARS = ["2025-26", "2026-27"];
export const FINANCIAL_YEARS = [2025, 2026];
export const RATE_TABLES = [
  {
    id: "income-tax",
    caption: "Income tax",
    period: "tax-year",            // or "financial-year"
    rows: [
      { label: "Personal Allowance", fact: "income-tax-personal-allowance", engine: "income_tax.personal_allowance", format: "gbp" },
      // a row without `engine` carries `value` (a number) and may carry `display` and `evidence`
    ],
  },
];
export function allRatesFactIds() { /* every row x every column of its period */ }
export function factId(row, column) { /* `${row.fact}-${column}`, column "2026-27" or "fy2026" */ }
export function formatFactValue(value, format) { /* rules below */ }
```

Fact id = row `fact` + `-` + column slug. Tax-year slugs are the labels (`2026-27`);
financial-year slugs are `fy2025`, `fy2026`. Engine file for a tax-year column `YYYY-YY` is
`se-YYYY-(YYYY+1).toml`; for `fyN` it is `ltd-N.toml`.

`formatFactValue(value, format)`:

| format | Rule | Example |
|---|---|---|
| `gbp` | `£` + `toLocaleString("en-GB")`, no decimals when whole, else two | `£12,570`, `£3.65` |
| `percent` | `(value * 100)` to at most two decimals, trailing zeros dropped, then `%` | `6%`, `16.5%`, `100%` |
| `pence` | `Math.round(value * 100)` + `p` | `45p` |
| `miles` | `toLocaleString("en-GB")` | `10,000` |
| `fraction` | smallest denominator 1 to 1000 that makes `value * d` whole (within 1e-9), as `n/d` | `3/200` |

A row's `display` overrides the formatted value (literal rows only). Its `evidence` is the text
the test looks for in the quote; it defaults to the displayed text.

Hide a control with the `hidden` attribute on its wrapper, so it leaves the tab order.

Income and expenses are entered excluding VAT. Every expense is taken as standard-rated. The form
says both beside the fields.

The limited-company period is the twelve months ending on `ratesYearEnd`. A free start date is
left out because `apportionCorporationTax` scales the two limits by each financial year's share
of the period, not by the period's length against a year, so a short period would keep full
limits. `twelveMonthPeriodStart(yearEnd)` returns the day after the same date one year earlier,
with 29 February treated as 28 February.

### `web/public/lib/rates/rates-compute.js`

```js
import { calculateExpectedTax } from "../diya-gl/tax/income-tax.js";
import { calculateCapitalAllowances } from "../diya-gl/tax/capital-allowances.js";
import { calculateMileageAllowance } from "../diya-gl/tax/mileage.js";
import { apportionCorporationTax, financialYearsInPeriod, financialYearRatesFor, financialYearNumber } from "../diya-gl/tax/corporation-tax.js";

export function twelveMonthPeriodStart(yearEnd) {}       // Date (UTC) -> Date (UTC)
export function vatPosition(inputs, vatTable) {}         // -> { outputVat, inputVat, vatDue, incomeForTax, expensesForTax, overThreshold }
export function cisDeducted(inputs, sourced) {}          // -> number
export function capitalAllowancesFor(inputs, capitalAllowancesTable, writingDownKey) {} // -> engine result
export function computeSelfEmployed(inputs, yearTables, sourced) {}
export function computeLimitedCompany(inputs, fyTablesByYear, sourced) {}
```

`inputs` is one object: `{ income, expenses, miles, equipment, poolBroughtForward, personalAllowance,
associatedCompanies, vatRegistered, vatScheme, flatRatePercent, cis, cisStatus, cisLabour, yearEnd }`,
numbers as numbers and `yearEnd` as an ISO date string.

Each switch, mapped to engine inputs:

| Step | Self-employed | Limited company |
|---|---|---|
| Tables | `SELF_EMPLOYED[ratesTaxYear]` | `fileFinancialYear = financialYearNumber(yearEnd)`; `LIMITED_COMPANY[fileFinancialYear]` |
| VAT | `vatPosition(inputs, tables.vat)` | same |
| Mileage | `calculateMileageAllowance(miles, tables.mileage)` | same |
| Capital allowances | `capitalAllowancesFor(inputs, tables.capital_allowances, "writing_down_allowance")` | key `"writing_down_allowance_main"` |
| Taxable profit | `incomeForTax - expensesForTax - mileage - capitalAllowances.total` | same |
| Tax | `calculateExpectedTax(taxableProfit, { ...tables, income_tax: { ...tables.income_tax, personal_allowance: personalAllowance } })` | see below |
| CIS | `cisDeducted(inputs, sourced)`, taken off the tax to pay | shown on its own line, not taken off corporation tax |

`vatPosition` (rate `r = vatTable.standard_rate`):

| Case | outputVat | inputVat | vatDue | incomeForTax | expensesForTax |
|---|---|---|---|---|---|
| VAT off | 0 | 0 | 0 | income | expenses |
| Standard | income × r | expenses × r | output − input | income | expenses |
| Flat rate | 0 | 0 | income × (1 + r) × flatRatePercent / 100 | income × (1 + r) − vatDue | expenses × (1 + r) |

`overThreshold` is `!vatRegistered && income > vatTable.registration_threshold`.

`capitalAllowancesFor` calls, mirroring `ltd.js`'s `Math.round(rate * 100)`:

```js
calculateCapitalAllowances(
  [
    { acquiredInYear: true, cost: inputs.equipment },
    { acquiredInYear: false, cost: 0, taxWrittenDownValue: inputs.poolBroughtForward },
  ],
  {
    investmentAllowancePercent: Math.round(table.annual_investment_allowance * 100),
    writingDownPercent: Math.round(table[writingDownKey] * 100),
  },
);
```

When `equipment` is over `sourced.aiaLimit`, show a status message that the limit is exceeded.
The figure stays the engine's.

`cisDeducted`: `cisLabour × { registered: sourced.cisRegisteredRate, unregistered: sourced.cisUnregisteredRate, gross: 0 }[cisStatus]`, 0 when CIS is off. When `cisLabour > income`, show a status message.

Limited company corporation tax:

```js
const periodEnd = new Date(`${inputs.yearEnd}T00:00:00Z`);
const periodStart = twelveMonthPeriodStart(periodEnd);
const fileFinancialYear = financialYearNumber(periodEnd);
const tables = fyTablesByYear[fileFinancialYear];      // missing -> throw "No rates for financial year N"
const { years, totalDays } = financialYearsInPeriod(periodStart, periodEnd);
const perYear = years.map((fy) => financialYearRatesFor(tables, fy.year, fileFinancialYear, fy.days));
const charge = apportionCorporationTax(taxableProfit, years, totalDays, {
  perYear,
  associatedCompanies: inputs.associatedCompanies,
  frankedInvestmentIncome: 0,
});
```

`financialYearRatesFor` reads `corporation_tax_previous_financial_year` for the earlier part of
a period that crosses 1 April, so `LIMITED_COMPANY` needs only the file for the year end.

Return shapes:

- `computeSelfEmployed` → `{ vat, mileageAllowance, capitalAllowances, taxableProfit, personalAllowance, incomeTax, class4, class2Voluntary, taxAndNi, cisDeducted, leftToPay, profitAfterTax, messages }`, where `incomeTax = r.income_tax`, `class4 = r.ni_class4_lower + r.ni_class4_upper`, `class2Voluntary = r.ni_class2`, `taxAndNi = r.total_tax_and_ni`, `leftToPay = taxAndNi - cisDeducted`, `profitAfterTax = taxableProfit - taxAndNi`.
- `computeLimitedCompany` → `{ vat, mileageAllowance, capitalAllowances, taxableProfit, periodStart, periodEnd, rows: charge.rows, taxBeforeRelief, marginalRelief, corporationTax: charge.tax, cisDeducted, profitAfterTax: taxableProfit - charge.tax, messages }`.

`messages` is an array of strings for the status area: over the VAT threshold, over the AIA
limit, CIS labour over income.

Class 2 uses `calculateExpectedTax`'s `ni_class2`, which is the voluntary amount below the
small profits threshold and nil above it. `calculateNIClass2` in `national-insurance.js` charges
52 weeks at or above the threshold, the pre-2024 rule, so the calculator never calls it.
Class 2 stays out of `taxAndNi`, as it does in the engine's `total_tax_and_ni`.

## 10. Risks

| Risk | Effect | Handling |
|---|---|---|
| 30-day source age with about 29 source files across two pages | `taxSources.test.js` fails for every branch once any file ages out | The skill's "Refresh all sources" run once a month; the board carries the refresh row |
| Engine figure differs from gov.uk | `ratesPage.test.js` fails on a real mismatch | Fix in spreadsheets `app/data`, publish, bump the pin |
| MTD1's names change before it merges | Imports in section 5 break | Use MTD1's landed names |
| `calculateNIClass2` encodes the pre-2024 Class 2 rule | A caller using it overstates Class 2 | The calculator uses `calculateExpectedTax`'s `ni_class2`; an engine fix is the spreadsheets repository's |
| `apportionCorporationTax` does not scale limits for a short period | Short periods get full limits | The calculator offers twelve-month periods only |
| Flat Rate Scheme and standard VAT use page arithmetic | VAT figures are not engine code | `vat.js` imports the generator; the arithmetic is three lines and has its own unit tests |
| AIA has no cap in the engine | Equipment over £1 million claims 100% | Status message; the figure stays the engine's |
| Nav grows to seven links | Mobile header wraps | MTD1 added `flex-wrap: wrap` to `.main-nav`; `mobileLayout.browser.test.js` runs in the commands above |
| diya-gl pin bump for the rates page also moves company-book | A bump changes two features | Bump only when a figure needs it, and run both features' tests |
